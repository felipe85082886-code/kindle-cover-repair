# Kindle cover repair

Repair the library thumbnail association for the existing book identity. Preserve the KFX file, its `.sdr` sidecar, and the catalog's reading fields. A successful run ends with a screen check on the Kindle, not just a database update.

## Choose the path

1. Identify the Kindle model and firmware, its USB mount, and the exact titles the user sees as broken. Back up readable book files, matching `.sdr` folders, thumbnails, and relevant user-visible reading caches before changing anything. Record hashes. Do not delete or resend a cloud personal document to fix its cover: that may create a new identity and lose progress.
2. Check the book's existing thumbnail file and catalog association. The internal catalog is `/var/local/cc.db`, outside the normal USB partition. If a thumbnail path exists and only its file is missing, replace that file at the same path after backing it up. If `p_thumbnail` is empty, use the guarded catalog workflow below. Do not assume every file lacking a `cover_image` marker needs repair.
3. A jailbroken Kindle may have SH Integration, which exposes `.sh` files in `documents` as launchable books. Test this with a short **read-only** scriptlet that exports `cc.db` and, if present, `cc.db-wal`/`cc.db-shm` to a distinct USB folder. Have the user safely disconnect, launch the scriptlet, and reconnect. Confirm the exported database opens. If the entry does not appear or run, stop the catalog workflow; do not install a jailbreak, hotfix, or launcher as a routine cover fix. Determine compatibility and obtain authorization before any system installation.
4. Run `scripts/inspect_catalog.py EXPORTED_CC_DB --kindle-root USB_MOUNT` to identify downloaded `PDOC` KFX rows with empty or broken thumbnails. Distinguish downloaded rows (`p_location` set) from cloud-only rows sharing the same content key. Ask the user to confirm which titles actually look wrong.
5. Find a cover matching the title and preferably the edition. Inspect the image and avoid confusing similarly titled books. Keep source URLs in the case record. For rows whose `p_thumbnail` is null, make a plan JSON with `[{"uuid":"...","cover":"/absolute/path/cover.jpg"}]` and run `scripts/build_repair.py --catalog EXPORTED_CC_DB --plan PLAN_JSON --output STAGING_DIR --kindle-root USB_MOUNT`. Read its generated manifest and script before copying. The builder accepts only downloaded `PDOC` KFX rows with null thumbnails and JPEG sources. It generates unique thumbnail filenames, exact UUID/content-key/location guards, a pre-update catalog backup, an atomic update, and progress snapshots.
6. Copy the staged files into their matching folders on the Kindle USB root; merge with existing `documents` and `system/thumbnails` folders instead of replacing those folders. Verify hashes. Safely eject. Have the user launch **Repair Kindle Covers** once and reconnect. Copy the generated `before.db`, `after.db`, status, and progress files to the local backup. Run `scripts/verify_repair.py --manifest MANIFEST_JSON --before BEFORE_DB --after AFTER_DB --status STATUS_TXT --kindle-root USB_MOUNT`. Require the success status and a verified difference limited to the planned `p_thumbnail` fields. If a check fails, inspect the log and snapshots before retrying; do not rerun blindly.
7. Remove only the temporary scriptlet and its export/repair folders from the Kindle after preserving local copies. Leave the new thumbnails. Safely eject and ask the user to verify the covers on screen. Record any edition mismatch or persistent display issue honestly.

The scripts operate on copies and staged files on the computer. The generated Kindle scriptlet performs the catalog write only when the user taps it on the device. Read [catalog-and-scriptlets.md](references/catalog-and-scriptlets.md) for schema details, the read-only export example, and failure handling.
